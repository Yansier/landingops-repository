# LandingOps 架构决策与待确认项

## 1. 已定决策（ADR 简版）

### ADR-001：控制面不进入站点运行时

- **状态**：已定，不可在 Phase 1B 擅自改变。
- **决定**：每个站点持有完整文件和本地配置；访客与原生后台不查询 LandingOps API/数据库。
- **理由**：故障隔离、低耦合、已部署站点连续性。
- **结果**：需要本地配置版本、原子写、恢复与上线后的独立性测试。

### ADR-002：V1 只支持一台宝塔

- **状态**：已定。
- **决定**：`baota_config` singleton；所有站点部署到同一台现有服务器。
- **结果**：不设计服务器表池、权重、路由、负载均衡或自动选择。多个 Cloudflare 账号不改变这一点。

### ADR-003：多 Cloudflare 连接按 Zone 明确选路

- **状态**：已定。
- **决定**：`primary_domain → zone → connection`，相同规范化 Zone 名在 V1 全局唯一。
- **结果**：Token 后端加密；团队只获授权主域名，不能自由指定连接。

### ADR-004：MySQL 持久化任务队列 + PHP CLI worker

- **状态**：已定，领取语法待 MySQL 版本联调。
- **决定**：V1 不先引入 Redis/RabbitMQ；Web 请求只提交任务，CLI worker 执行长流程。
- **理由**：部署量轻、现有栈足够、减少运维组件。
- **结果**：需要租约、心跳、幂等、退避、未知结果核验和步骤持久化。若量级数据证明不够，再新增 ADR。

### ADR-005：批量部署复用单站引擎

- **状态**：已定。
- **决定**：一个批次只聚合多个独立单站任务。
- **结果**：允许部分成功；重试单个失败项；没有第二套批量编排逻辑。

### ADR-006：外部资源默认不覆盖、不接管

- **状态**：已定。
- **决定**：既有 DNS、宝塔站点与目录默认阻止。已指向本机且兼容的 DNS 可核验复用，但不取得删除权。
- **结果**：补偿仅删除本步骤创建、外部 ID/内容未变且所有权证据充分的资源。

### ADR-007：模板和资产不可变版本化

- **状态**：已定。
- **决定**：模板版本 ZIP、备用 HTML 和供应商组件以版本+SHA-256 保存，发布后不原位替换。
- **结果**：模板授权撤销和默认资产切换不改动已部署实例；实例升级需显式流程。

### ADR-008：LTS v1.0 以 `index.html` 为必需源入口

- **状态**：已定。
- **决定**：ZIP 根必须有 `index.html`、`landingops.json`；可配置模板有 `config.schema.json`。
- **结果**：供应商 `index.php/core.php` 独立装配，`admin/index.php` 是另一可选入口；三者不能混淆。

### ADR-009：站点本地配置采用乐观锁与原子替换

- **状态**：已定。
- **决定**：本地信封含 schema version、revision、hash；LandingOps 和原生后台都提交 expected revision。
- **结果**：冲突返回 409；本地写成功而数据库失败时，以本地运行事实协调，不用数据库旧值覆盖。

### ADR-010：原生后台默认关闭并真正阻断

- **状态**：已定。
- **决定**：只有模板声明支持且实例创建时显式启用才发布/放行；使用本站独立密码。
- **结果**：关闭时 Nginx 规则或不发布入口；LandingOps 权限体系不扩展到原生后台。

### ADR-011：不建设模板视觉预览能力

- **状态**：已定。
- **决定**：模板库无截图、效果图、缩略图、自动截图和独立预览服务。
- **结果**：数据库、manifest 和 API 契约均不包含相关字段。

### ADR-012：外部供应商组件保持独立与合规边界

- **状态**：已定。
- **决定**：默认不修改供应商核心；不提交潜在密钥；不设计审核规避或差异内容分流。
- **结果**：只记录版本、哈希、PHP 要求、兼容性和合法的通用备用/维护页能力。

## 2. 待联调项（不改变产品约束）

以下问题必须在 Phase 1B 编码相应适配器前通过测试环境或官方文档确认：

1. 目标宝塔面板版本、API 鉴权/来源限制、站点列表与创建、域名绑定查询、PHP 版本绑定、证书申请、HTTPS 设置和状态查询的实际能力。
2. Cloudflare Token 的账号/Zone 最小权限、Zone/记录分页、记录类型与代理状态、限流/重试响应、通配符查询方式。
3. 服务器预期公网 IPv4/IPv6、是否使用 Cloudflare Proxy、默认 TTL、是否允许 CNAME 目标及通配符处理政策。
4. 生产 MySQL 精确版本，是否支持 `SKIP LOCKED`；不支持时使用原子条件更新领取。
5. 宝塔生产环境的 PHP 版本、扩展、Nginx include 管理方式、站点根父目录和文件所有者。
6. SSL 默认签发方式、传播等待上限、失败时是否允许临时 HTTP（当前设计默认不激活）。
7. 供应商组件实际文件、许可证、PHP 约束、配置入口和密钥迁移方式。任何源文件到位前都不能假定实现细节。

## 3. 需要业务方确认的非阻塞问题

这些选择不会阻碍 Phase 1A 定稿，但应在 Phase 1B 对应功能开始前确认：

1. **删除/下线策略**：V1 是否提供显式下线，以及保留站点目录、DNS 和证书的默认期限。当前方案不自动删除已部署站点。
2. **DNS 默认值**：新 A/AAAA/CNAME 的 Proxy 状态与 TTL。当前只定义“不得覆盖”，没有替用户决定具体值。
3. **HTTP 失败策略**：SSL 尚未成功时，是保持站点不可激活，还是允许管理员显式启用临时 HTTP。建议默认不可激活。
4. **原生后台密码交付**：创建时由用户输入还是系统生成一次性密码；建议用户输入或一次性显示，服务端只留哈希。
5. **配置备份保留**：每实例保留版本数量/天数。建议至少保留最近 10 个成功版本和 30 天审计，但需结合磁盘政策。
6. **模板上传限制**：30 MiB ZIP、100 MiB 解压、2,000 文件的默认值是否需要收紧。
7. **外链策略**：模板是否允许第三方 CDN/字体/分析脚本；建议默认报告并按域名白名单审批。
8. **备用页应用语义**：新部署失败时是否人工选择使用，还是某些合法维护状态自动使用。当前不会按访客身份差异分流。
9. **团队管理员的用户管理细节**：能否创建/停用本团队员工，还是只由总管理员操作；PRD 暂定允许管理本团队员工。

## 4. 未发现的“需求矛盾”与已澄清的歧义

Phase 1A 未发现必须反转既定产品约束的真实矛盾。以下表面歧义已通过边界澄清：

- “上传 ZIP 的入口固定 `index.html`”与“部署后可能为 `index.php`”不冲突：前者是模板源内容，后者是独立组件可能提供的运行入口。
- “LandingOps 能读写配置”与“站点不依赖 LandingOps”不冲突：控制面只在管理操作时通过本地文件适配器发布，访客请求不回查控制面。
- “复用已指向本机的 DNS”与“默认不覆盖”不冲突：复用前必须核验，且不修改、不删除、不取得所有权。
- “撤销模板授权”只撤销未来使用权，不是实例下线命令。

## 5. Phase 1B 建议顺序（需验收后再启动）

1. 固化 LTS/本地配置 JSON Schema 与恶意 ZIP 测试语料，先实现纯离线验证器。
2. 建立数据库迁移、固定角色授权中间件和密钥加密抽象。
3. 实现任务状态机、MySQL 租约 worker 与模拟适配器，覆盖超时未知结果和补偿测试。
4. 在隔离测试环境联调 Cloudflare、再联调目标宝塔版本；将能力差异封装在适配器。
5. 实现站点构建、本地配置原子写和后台真实开关；完成断开 LandingOps 的独立性测试。
6. 最后实现最小 Vue 管理界面，调用已验收 API 契约，不在前端复制权限逻辑。

Phase 1A 到此停止；以上顺序只是后续建议，不代表已授权实施。
